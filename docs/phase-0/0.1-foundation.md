# Phase 0.1 — Requirements & Canonical Schemas

## Purpose
Establish the contracts every later POC checkpoint must obey so geography, weather, events, news, sources, caching, and AI synthesis do not evolve as incompatible one-off structures.

## Implemented
- Product requirements and explicit non-goals.
- Logical architecture and failure boundaries.
- Canonical identity/provenance/time/versioning rules.
- Event/news taxonomy baseline.
- Source reliability/provenance policy.
- AI grounding and regeneration policy.
- Cache/freshness policy separating live data from the Daily Scoop.
- Versioned JSON Schemas for geography, source, event, story, weather, and Daily Scoop.
- Valid fixtures plus negative contract tests for provenance/citations.

## Exit criteria
1. Every planned ingestion subsystem has a canonical target record.
2. Canonical records retain source identity and retrieval timestamps.
3. Daily Scoop sections cite canonical record IDs.
4. Cache semantics distinguish fresh, stale, and expired data.
5. Schemas are versioned and machine-validatable.
6. Representative fixtures pass validation.
7. Breaking contract changes require an explicit version decision.

## Deferred
Real POC market selection/geography lookup, live weather integration, event/news source adapters, deduplication thresholds, production storage selection, LLM provider/model choice, and polished UI.

## Phase 0.2 handoff
Implement `GeographyContext` against a real location and prove coordinate input, city/county resolution, stable county identity, adjacent counties, radius/distance rules, timezone, included/excluded regions, and deterministic region IDs for caches/Scoops.
