# Phase 0.2 — Geography POC

## Goal
Prove that Local Scoop can turn a user's coordinates into a stable geographic context suitable for source filtering, event distance, cache identity, and a region-scoped Daily Scoop.

## POC market
- City: Raleigh, North Carolina
- Home county: Wake County
- County GEOID: `37183`
- Representative coordinates: `35.7796, -78.6382`
- Timezone: `America/New_York`

The POC is deliberately US/NC bounded. National timezone resolution and a national state-reference table are deferred until the geography contract has survived live use.

## Implemented
- validated WGS84 coordinate value object;
- Census Geocoder coordinate lookup adapter using `Public_AR_Current` + `Current_Current`;
- parser for State, County, Incorporated Place, and Census Designated Place layers;
- stable county identity as `us:county:<GEOID>`;
- parser/index for the Census Bureau county adjacency file;
- 2025 Wake County adjacency fixture with shared-boundary length retained;
- county, adjacent-county, radius, and custom coverage modes;
- explicit include/exclude behavior;
- deterministic coverage-region identity (`geo1:<sha256-prefix>`) for caches and Daily Scoop uniqueness;
- Haversine point-to-point distance/radius utilities;
- bounded North Carolina timezone resolver;
- serialization back into the Phase 0.1 `GeographyContext` contract.

## Wake adjacency verified against 2025 Census data
Wake County has seven adjacent counties in the 2025 national adjacency file:

| GEOID | County | Shared boundary (m) |
|---|---|---:|
| 37037 | Chatham County | 37,524 |
| 37063 | Durham County | 41,318 |
| 37069 | Franklin County | 41,836 |
| 37077 | Granville County | 19,845 |
| 37085 | Harnett County | 20,104 |
| 37101 | Johnston County | 53,367 |
| 37127 | Nash County | 0 |

A zero boundary length is preserved because the 2025 Census file explicitly uses `0` for point-to-point adjacency.

## Region identity
A Scoop/cache region is not identified only by city name. The region ID hashes canonicalized coverage configuration:
- home county GEOID;
- coverage mode;
- sorted included county GEOIDs;
- sorted exclusions;
- radius, when applicable.

Equivalent configurations produce the same ID regardless of input ordering; changing coverage changes the ID.

## Failure behavior
- invalid latitude/longitude: reject;
- Census response with no county: reject;
- radius mode without positive radius: reject;
- excluding the home county: reject;
- unsupported state in the bounded POC timezone resolver: reject explicitly rather than guessing.

## Deferred
- national timezone polygon lookup;
- national state FIPS/abbreviation reference table;
- downloading/caching the complete national adjacency file at runtime;
- postal-address geocoding UI;
- county polygon intersection for radius searches;
- drive-time routing;
- non-US geography.

## Exit assessment
Phase 0.2 succeeds if tests prove deterministic identity, correct Wake adjacency, coordinate parsing, explicit failures, and distance behavior. Live Census calls remain integration acceptance rather than a unit-test dependency.
