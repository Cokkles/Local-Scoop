# Phase 0.3 — Weather POC

## Purpose

Prove that Local Scoop can attach detailed, source-attributed, cache-aware weather to the stable Phase 0.2 Geography Context without using AI for meteorological facts.

## POC provider model

### National Weather Service — authoritative U.S. source

The NWS API is used for:

- coordinate-to-grid/endpoint discovery through `/points/{lat},{lon}`;
- nearest returned observation station and latest observation;
- hourly forecast;
- NWS 12-hour extended forecast periods covering the next seven days;
- active alerts for the configured point.

The client sends the User-Agent required by NWS API guidance.

### Open-Meteo — optional supplemental detail

Open-Meteo is used to enrich the NWS record with detail useful to the expanded weather UI, including apparent temperature, dew point, humidity, precipitation amounts, cloud cover, visibility, gusts, and UV. Requests explicitly select Fahrenheit, mph, inches, the Geography Context timezone, and a bounded forecast horizon.

NWS remains primary for observed temperature and the core NWS hourly forecast fields. Provider disagreement is not averaged or silently reconciled.

## Canonical weather snapshot

A weather snapshot is keyed to the Local Scoop `region_id` and includes:

- current conditions;
- normalized hourly periods;
- NWS extended day/night forecast periods;
- active alerts;
- provider provenance and exact endpoints;
- separate forecast and alert retrieval timestamps;
- freshness state;
- provider errors.

Weather IDs use a deterministic `wx1:` hash derived from the effective region and component retrieval timestamps.

## Cache policy

POC defaults:

- forecast/current refresh target: 30 minutes;
- active alerts refresh target: 2 minutes;
- stale-if-error window for the authoritative forecast: 6 hours.

Alerts refresh independently from the heavier forecast/detail request. A normal app refresh inside both TTLs performs no provider request.

If the optional detail provider fails, NWS data is still returned with an explicit provider error. If the alert endpoint fails, forecast data remains available. If NWS forecast retrieval fails and a last-known-good snapshot is inside the bounded stale window, Local Scoop returns it as `stale`. Once expired, the service raises an unavailable state rather than presenting old weather as current.

## Phase 0.3 exit criteria

- NWS point discovery is deterministic and validates required links.
- Current NWS station observations normalize into display units.
- NWS hourly periods normalize into one canonical model.
- NWS extended day/night periods preserve the next-seven-days forecast text and values.
- NWS alerts preserve identity, headline, severity, urgency, certainty, area, effective/expiry timing, sender, and source URL. Full alert body/instruction retention is deferred beyond this checkpoint.
- Open-Meteo supplemental detail merges without overriding designated NWS-primary facts.
- Cache prevents repeated provider calls while fresh.
- Alert refresh is independent from forecast refresh.
- Provider failures degrade explicitly and safely.
- Canonical output preserves source IDs and endpoint provenance.
- Weather schema requires source-backed current/hourly/alert data.
- Deterministic tests require no network.

## Deferred

- radar imagery/rendering;
- air quality;
- lightning nowcasting;
- tropical/storm-specialized products;
- nationwide field testing outside the Raleigh/Wake POC;
- persistent Redis/database cache;
- push notifications;
- polished weather dashboard.

## Phase 0.4 handoff

Use the stable geography region plus weather subsystem to begin real local event-source discovery and source-registry scoring for Raleigh/Wake and surrounding counties.
